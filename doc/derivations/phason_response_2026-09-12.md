## Numerical API scope

The response and inverse functions operate on scalar inputs; q=0 is explicitly rejected with a uniform-field-degeneracy explanation. The pole oracle is deliberately narrower than the theorem: it attempts nonzero-coupling roots only for beta>=1e-10,1-beta>=1e-10 and1e-6<=u0<=1e6, with root-count/damping/residual/separation checks. Outside that window it returns numerical_available=false and no pole/Q while retaining representable analytic bounds/classification. The beta=0 acoustic pole is exact. If even an analytic coefficient cannot be represented under the normal-binary64 policy, NumericalUnavailable (a ValueError) is raised instead of emitting a false zero/subnormal. The flag collision records literal floating endpoint equality, not certified symbolic equality; near_collision uses a128eps relative proximity heuristic and withholds numerical poles. All beta>=8/9 reports conservatively leave ancestry_available=false even when an oscillatory pair exists. Just above the cusp, unresolved endpoint width (hi-lo<=128eps max(lo,hi)) produces classification_available=false, no interval and no numerical pole; the code does not sort inverted endpoints or present a collapsed interval as resolved. Unresolved small softening in the full real modulus is rejected rather than hidden. These policies neither narrow the analytic theorem nor provide certified solver error bounds.
